# supplier-inn-kpp — отдельная консольная утилита на Rust

**Не является модулем ID-Control и не изменяет его исходники, БД, API или настройки.**

Читает текстовые Word-документы `.doc` (Word 97–2003) и `.docx` в одном файле или в каталоге рекурсивно. С помощью установленного LibreOffice Writer переводит документ во временный XHTML, сохраняющий структуру таблиц. Затем отдельно анализирует ячейки/столбцы «Поставщик», «Продавец», «Исполнитель», «Подрядчик», не смешивая их с «Покупатель», «Заказчик». Проверяет контрольное число ИНН (10 или 12 знаков) и длину КПП (9 цифр).

## Установка (Ubuntu 24.04)

```bash
sudo apt update
sudo apt install -y libreoffice-writer cargo
unzip supplier-inn-kpp-cli.zip
cd supplier-inn-kpp-cli
cargo test
cargo build --release
```

Никакие сторонние Rust-библиотеки не используются — Cargo не нужно скачивать зависимости из crates.io.

Для Windows установите LibreOffice и Rust (rustup), откройте PowerShell в каталоге проекта, выполните `cargo test`, `cargo build --release`. Если LibreOffice установлен не по стандартному пути, задайте `LIBREOFFICE_BIN` с путём к `soffice.exe`.

## Запуск

```bash
# Один файл
./target/release/supplier-inn-kpp '/путь/к/договор поставки.doc'

# Все .doc/.docx, включая подпапки
./target/release/supplier-inn-kpp '/путь/к/договора'

# Для скриптов — JSONL
./target/release/supplier-inn-kpp '/путь/к/договора' --json > result.jsonl

# Ненулевой код возврата, если хоть один документ не распознан
./target/release/supplier-inn-kpp '/путь/к/договора' --strict
```

Проверочный файл `договор поставки ДП-30-10Н БАЗИС Нахимова.doc` должен дать:

```text
[OK] ... | Поставщик ИНН=3025035441 КПП=302501001
ИТОГО: файлов 1, найдено 1, не подтверждено 0, ошибки чтения 0
```

По договору покупатель ООО СЗ «РЭС-НАХИМОВА» имеет другие реквизиты — ИНН 3000011270 / КПП 300001001, их присваивать поставщику нельзя.

## Измерение времени работы `main()`

При каждом запуске программа записывает в **stderr** три строки — время начала, завершения и затраченное время:

```text
[TIME] Измерение начато (UTC): 2026-11-02T09:11:01.008Z
[OK] C:\Documents\contract.doc | Поставщик ИНН=3025035441 КПП=302501001
ИТОГО: файлов 1, найдено 1, не подтверждено 0, ошибки чтения 0
[TIME] Измерение завершено (UTC): 2026-11-02T09:11:03.390Z
[TIME] Time elapsed (main): 00:00:02.382 (2.382 s)
```

*Значения в примере иллюстративные.* Точность измерения — миллисекунды, время UTC в ISO 8601. `Instant` измеряет длительность монотонными часами — сюда входит запуск и обработка всех файлов, включая конвертацию LibreOffice. Начало и окончание фиксируются через `SystemTime`.

В режиме `--json` строки `[TIME]` идут в `stderr`, поэтому JSONL в `stdout` остаётся машиночитаемым:

```powershell
.\target\release\supplier-inn-kpp.exe "C:\Documents" --json > result.jsonl
```

Тесты времени включены в `cargo test`.

## Как устроены ограничения

- Бинарный `.doc` и `.docx` должны корректно открываться LibreOffice. Старые повреждённые или защищённые паролем файлы могут не прочитаться.
- `.doc` с **одними сканами, без распознаваемого текстового слоя**, потребует отдельного OCR; программа не делает вид, что нашла реквизиты на изображении.
- Отсутствующие, ошибочные или неоднозначные реквизиты не угадываются. Статусы: `found`, `not_found`, `ambiguous`, `error`.
- Обрабатывает реквизиты поставщика из Word-файлов, но не юридически проверяет действительность организации.
- Исходные документы не изменяются и не отправляются ни в какие внешние сервисы.

## Тестирование

`cargo test` проверяет двухколоночные таблицы, отдельные и объединённые ИНН/КПП, ошибочный ИНН, отсутствие поставщика, конфликт сторон, разные регистры `.DOC` и `.DOCX`.

`bash scripts/smoke-conversion.sh '/путь/к/файлу.doc'` проверяет установленную конвертацию LibreOffice. Для полноценного функционального теста запустите собранный бинарник на переданном договоре.

### Интеграционный тест на настоящем DOC

В архив включён тест, который запускается **только при наличии** переменной `SUPPLIER_DOC_TEST_FILE`; оригинальный договор в архив не копируется:

```bash
SUPPLIER_DOC_TEST_FILE='/путь/к/договор поставки ДП-30-10Н БАЗИС Нахимова.doc' cargo test --test real_doc -- --nocapture
```


## DOCX с ИП (исправление 1.1.0)

Версия 1.1.0 исправляет ошибку `status: ambiguous` для документов, где
поставщик/исполнитель — индивидуальный предприниматель с 12-значным ИНН,
а КПП отсутствует по закону. Обычные ООО с 10-значным ИНН по-прежнему
требуют девятизначный КПП. Двухколоночные таблицы Word обрабатываются
раздельно: КПП заказчика не может стать КПП исполнителя.

Пример для файла `Спецификация_2_Звёздная_ИП Белан.docx`:

```json
{"file":"Спецификация_2_Звёздная_ИП Белан.docx","status":"found","supplier_inn":"402709591781","supplier_kpp":null}
```

Для `--json` отсутствие КПП у ИП — `null`, а не ошибка и не строка `""`.
При обычном выводе показывается `КПП=не предусмотрен (ИП)`.

### Windows PowerShell

```powershell
cargo test
cargo build --release
.\target\release\supplier-inn-kpp.exe '.\Спецификация_2_Звёздная_ИП Белан.docx' --json
```

Интеграционный тест двухколоночного DOCX с ИП автоматически запускается
через `cargo test` и требует LibreOffice (как и основная программа).
Для запуска теста непосредственно на своём DOCX:

```powershell
$env:SUPPLIER_IP_DOCX_TEST_FILE = '.\Спецификация_2_Звёздная_ИП Белан.docx'
cargo test --test real_doc actual_ip_docx -- --nocapture
```

Конвертация DOC/DOCX осуществляется локально через LibreOffice;
исходные документы не изменяются. Время выполнения main выводится в stderr,
чтобы JSON в stdout оставался корректным.


## Регрессионный тест на реальном DOCX ИП Белан (v1.1.1)

В `tests/fixtures/belan_specification_original.docx` находится оригинал
приложенной пользователем спецификации. Тест без `SKIP` проверяет извлечение
ИНН **402709591781** от **Исполнителя**, отсутствие КПП (`null`), а также
что ИНН/КПП заказчика не попали в результат.

```powershell
cargo test belan_inn_checksum_is_correct -- --nocapture
cargo test belan_supplier_inn_in_docx_like_two_column_xhtml -- --nocapture
cargo test --test belan_regression -- --nocapture
cargo build --release
.\target\release\supplier-inn-kpp.exe '.\Спецификация_2_Звёздная_ИП Белан.docx' --json
```

Тест `belan_regression` требует установленного LibreOffice. Для реального
файла ожидается `status=found, supplier_inn=402709591781, supplier_kpp=null`.

Проверяйте строку версии `Compiling supplier-inn-kpp v1.1.1`. Если Cargo пишет
`v1.0.0`, вы собираете старую библиотеку `src/lib.rs`, которая требует КПП
для каждого ИНН и возвращает `ambiguous` для ИП. Одного `main.rs` недостаточно.
